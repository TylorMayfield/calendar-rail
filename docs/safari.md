# macOS Safari build

The shared extension is under `extension/`. The macOS-only Swift containing app uses a deterministic Xcode project generated by `node scripts/generate-xcode.cjs`. The installed converter was attempted with:

```sh
xcrun safari-web-extension-converter extension \
  --project-location safari --app-name 'Calendar Rail' \
  --bundle-identifier com.tylormayfield.calendarrail \
  --macos-only --swift --no-open --no-prompt
```

The converter could not access its source directory under this execution sandbox, including a test under /tmp. A native wrapper was authored instead. The Xcode project references the shared files. The universal arm64/x86_64 build compiles, and the containing app launches. Ad-hoc signing alone did not make its extension appear in Safari Settings; installed-extension acceptance is still outstanding. Run from the repository root. No source copies need to be maintained separately.

Build without signing for compile validation:

```sh
xcodebuild -project 'safari/Calendar Rail.xcodeproj' \
  -scheme 'Calendar Rail' -configuration Release \
  -derivedDataPath build/safari CODE_SIGNING_ALLOWED=NO build
```

For App Store distribution, select the existing developer team for BOTH targets and use a unique app bundle identifier and extension bundle identifier. Archive and export for App Store Connect with valid distribution signing and provisioning. Do not create paid enrollments or accept new agreements without the account holder's approval.

Alternatively, when available for the existing App Store Connect account, upload the shared extension ZIP through the Safari Web Extension Packager on the app's Xcode Cloud tab, then test the resulting build via TestFlight. Verify included compute capacity before packaging and do not buy additional compute.

Unsigned build success only verifies compilation. It does not prove Safari runtime behavior, real-account routing, signing, App Store upload or acceptance.

App Store Connect cloud packaging uses packages/calendar-rail-safari-1.1.1.zip. Its manifest display name is Calendar Rail, matching the app record; executable content scripts are identical to Chrome. The Safari archive adds the original 1024px icon. The Chrome archive retains its compatibility title. Run npm run package to regenerate both.
